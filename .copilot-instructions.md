# Copilot Instructions for ansible-role-ping-test

## Project Overview
This is an Ansible role for testing connectivity to managed hosts using the ping module. It supports both Linux and Windows systems and includes OS detection and execution result tracking.

## Code Style and Standards

### Ansible Best Practices
- Use FQCN (Fully Qualified Collection Names) for all modules: `ansible.builtin.ping`, not `ping`
- Follow YAML best practices: 2-space indentation, proper quoting
- Use `block` and `rescue` for error handling
- Register task results for later use
- Use Jinja2 filters with defaults: `{{ variable | default('fallback') }}`

### Naming Conventions
- Task names: Descriptive, sentence case with proper capitalization
- Variables: Use snake_case (e.g., `execution_result_return_code`)
- Role names: Use underscores, lowercase (e.g., `ping_test`, `execution_result`)

### File Organization
- `tasks/main.yml`: Primary task file with logical task ordering
- `defaults/main.yml`: Default variables for the role
- `vars/main.yml`: Variables with higher precedence
- `meta/main.yml`: Role metadata and dependencies
- `handlers/main.yml`: Handler definitions
- `tests/`: Test playbooks and inventory

## Role Architecture

### Task Flow
1. **OS Detection**: Gather system facts (distribution, version, architecture)
2. **Linux Ping Test**: Execute `ansible.builtin.ping` for Linux systems
3. **Windows Ping Test**: Execute `ansible.builtin.win_ping` for Windows systems
4. **Execution Result Tracking**: Call `execution_result` role to capture outcomes

### Error Handling
- All ping tests use block/rescue pattern
- Success and failure paths both capture execution details
- Failed tasks include comprehensive error information (stdout, stderr, exception, warnings)

## Development Guidelines

### When Adding New Features
- Always include OS detection if system-specific
- Use block/rescue for new tasks that might fail
- Register results for transparency
- Include debug output where helpful
- Update README.md with new functionality

### Testing
- Test playbooks go in `tests/` directory
- Include both success and failure scenarios
- Test on multiple OS families (Linux, Windows)
- Verify execution_result role integration

### Documentation
- Keep README.md current with usage examples
- Document all role variables in defaults/main.yml with comments
- Include inline comments for complex Jinja2 expressions
- Update meta/main.yml with accurate metadata

## Dependencies
- Requires `execution_result` role for result capture
- Uses Ansible core modules from `ansible.builtin` collection

## Common Tasks
- **Add new OS detection fact**: Update gather_subset in "Collect OS facts" task
- **Modify ping behavior**: Edit block tasks under Linux/Windows Ping Test
- **Change error handling**: Modify rescue blocks and execution_result vars
- **Add variables**: Define in defaults/main.yml with documentation

## Code Quality
- Validate YAML syntax before committing
- Use `ansible-lint` for best practices checking
- Test role with `ansible-playbook` against test inventory
- Ensure idempotency where applicable
